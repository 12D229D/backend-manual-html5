🟢 Guía Práctica de Node.js & npm

Node.js es el runtime JavaScript que permite ejecutar JS en el servidor usando el motor V8 de Chrome. Con su modelo asíncrono orientado a eventos es ideal para construir APIs, microservicios y servidores escalables.

¿Qué es Node.js?

Node.js es un entorno de ejecución de JavaScript construido sobre el motor V8 de Google Chrome. Lo creó Ryan Dahl en 2009 para resolver el problema de la concurrencia en servidores tradicionales, introduciendo un modelo de I/O no bloqueante orientado a eventos.

Características clave

  • Single-threaded aunque puede delegar tareas a libuv (un thread pool C++) para operaciones de disco/criptografía.
  • Asincronía nativa mediante callbacks, Promesas y async/await.
  • NPM: el ecosistema de paquetes más grande del mundo, con más de 2 millones de paquetes publi­cados.
  • Cross-platform: corre en Windows, macOS, Linux y Docker.
💡 ¿Cuándo usar Node.js?

Ideal para APIs REST, microservicios, servidores en tiempo real (WebSockets, chat), streaming, herramientas CLI yBFFs. Evítalo para tareas intensivas en CPU (procesamiento de imágenes, machine learning).

Event Loop y Asincronía

El Event Loop es el núcleo del modelo de concurrencia de Node.js. Es un bucle que observa continuamente las colas de callbacks listos para ejecutarse en el hilo principal, mientras libuv procesa I/O paralelo en segundo plano.

event-loop.js - lectura asíncrona de fichero 
const fs = require('node:fs/promises');

async function leer() {
  console.log('1. Antes de await');
  const datos = await fs.readFile('./paquetes.json', 'utf8');
  console.log('2. Datos leídos:', datos.length, 'bytes');
  console.log('3. Después de await');
}

console.log('0. Inicio');
leer();
console.log('4. Fin del script síncrono');

// Orden de salida:
// 0. Inicio
// 1. Antes de await
// 4. Fin del script síncrono
// 2. Datos leídos: N bytes
// 3. Después de await
⚠️ No bloquees el Event Loop

Una operación síncrona larga (un bucle de millones de iteraciones, JSON.parse gigante o crypto.pbkdf2Sync) congela todas las peticiones del servidor. Usa las versiones asíncronas (*Sync sólo en arranque).

Sistema de Módulos: CommonJS vs ESM

Node soporta dos sistemas de módulos, configurables mediante "type": "module" en package.json.

Aspecto CommonJS (CJS) ES Modules (ESM)
Sintaxisrequire() / module.exportsimport / export
CargaSíncronaAsíncrona (estática)
Extensión.js por defecto.mjs o .js con type:module
Top-level await❌ No soportado✅ Soportado
Tree-shakingLimitadoCompleto (bundler)
CommonJS 
// matematicas.js
function suma(a, b) { return a + b; }
module.exports = { suma };

// app.js
const { suma } = require('./matematicas');
console.log(suma(2, 3)); // 5
ES Modules 
// matematicas.mjs
export function suma(a, b) { return a + b; }

// app.mjs
import { suma } from './matematicas.mjs';
console.log(suma(2, 3)); // 5

npm y package.json

npm (Node Package Manager) es el gestor de paquetes oficial. package.json es el manifiesto de tu proyecto: declara dependencias, scripts y metadatos.

Comandos básicos de npm 
# Inicializar un nuevo proyecto Node
npm init -y

# Instalar una dependencia de producción
npm install express

# Instalar una dependencia de desarrollo
npm install --save-dev nodemon

# Ejecutar un script definido en package.json
npm run dev

# Ejecutar un binario local instalado
npx prisma migrate dev

# Auditar vulnerabilidades conocidas
npm audit
package.json típico 
{
  "name": "mi-backend",
  "version": "1.0.0",
  "main": "src/server.js",
  "type": "module",
  "scripts": {
    "dev":   "nodemon src/server.js",
    "start": "node src/server.js",
    "test":  "jest"
  },
  "dependencies": {
    "express": "^4.19.2",
    "pg":       "^8.11.5"
  },
  "devDependencies": {
    "nodemon": "^3.1.0",
    "jest":    "^29.7.0"
  },
  "engines": {
    "node": ">=18"
  }
}
📌 package-lock.json

Commitea package-lock.json para fijar versiones exactas y garantizar instalaciones reproducibles entre desarrolladores y CI/CD. No commitees la carpeta node_modules/.

Servidor HTTP "Hola Mundo"

Node incluye el módulo nativo http para crear servidores sin ninguna dependencia externa. Sin embargo, en proyectos reales conviene usar un framework como Express (ver guía siguiente).

server.js - servidor HTTP nativo 
import { createServer } from 'node:http';

const PORT = process.env.PORT ?? 3000;

const server = createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({
    mensaje: 'Hola Mundo desde Node.js',
    metodo: req.method,
    ruta:   req.url,
    hora:   new Date().toISOString()
  }));
});

server.listen(PORT, () => {
  console.log(`Servidor escuchando en http://localhost:${PORT}`);
});

Ejecútalo con:

terminal 
node server.js
# → Servidor escuchando en http://localhost:3000

# En otra terminal prueba con curl:
curl http://localhost:3000/api
