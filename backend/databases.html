SQL vs NoSQL: ¿cuál elegir?

No existe un ganador universal; la elección depende del tipo de datos, la consistencia requerida y la escala esperada.

Criterio SQL (Relacional) NoSQL (Documental / Clave-Valor)
EjemplosPostgreSQL, MySQL, SQLite, MS SQLMongoDB, Redis, DynamoDB, Cassandra
EsquemaRígido, tablas y columnas definidasFlexible, documentos JSON
TransaccionesACID garantizadasACID parcial (Mongo 4+ lo soporta)
ConsultasSQL declarativo + JOINsAPI del driver / agregaciones
Casos idealesDatos con relaciones fuertes, financieros, ERPCatálogos, contenido variable, caché, IoT
EscaladoVertical (más CPU/RAM)Horizontal (sharding nativo)
💡 Regla general

Si tus datos encajan en tablas relacionales y necesitas consistencia transaccional estricta, usa PostgreSQL. Si los documentos son jerárquicos y varían mucho, valora MongoDB.

PostgreSQL con el driver nativo

PostgreSQL es el motor relacional open source más potente. El paquete pg permite conectarse y ejecutarconsultas preparadas.

config/db.js - pool de conexiones 
import pg from 'pg';
const { Pool } = pg;

export const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  // produc­ción: usar SSL y limitar pool
  ssl: process.env.NODE_ENV === 'production' ? { rejectUnauthorized: false } : false,
  max: 10                          // máx. 10 conexiones reutilizables
});

pool.on('error', (err) => console.error('Error inesperado en pool:', err));
usuarios.repository.js - consultas preparadas (anti-SQLi) 
import { pool } from '../config/db.js';

export async function listarUsuarios({ limite = 20, offset = 0 } = {}) {
  const { rows } = await pool.query(
    'SELECT id, email, nombre, rol FROM usuarios ORDER BY id LIMIT $1 OFFSET $2',
    [limite, offset]
  );
  return rows;
}

export async function crearUsuario({ email, passwordHash, nombre }) {
  const { rows } = await pool.query(
    `INSERT INTO usuarios (email, password_hash, nombre)
     VALUES ($1, $2, $3)
     RETURNING id, email, nombre, rol`,
    [email, passwordHash, nombre]
  );
  return rows[0];
}
🚨 Jamás concatenes valores en SQL

Construir SQL con template strings como `... WHERE id = ${req.params.id}` abre la puerta a SQL Injection. Usa SIEMPRE consultas parametrizadas ($1, $2, …).

MongoDB con Mongoose

Mongoose es la librería más popular para modelar datos en MongoDB desde Node.js. Define esquemas con validaciones y tipos, y genera un modelo listo para CRUD.

models/usuario.model.js 
import mongoose from 'mongoose';

const usuarioSchema = new mongoose.Schema({
  email:    { type: String, required: true, unique: true, lowercase: true },
  nombre:   { type: String, required: true, trim: true },
  password: { type: String, required: true, minlength: 8, select: false },
  rol:      { type: String, enum: ['admin', 'user'], default: 'user' },
  creadoEn: { type: Date, default: Date.now }
});

// Índice compuesto para búsquedas
usuarioSchema.index({ nombre: 1, creadoEn: -1 });

export const Usuario = mongoose.model('Usuario', usuarioSchema);
usuarios.service.js - operaciones CRUD 
import { Usuario } from '../models/usuario.model.js';

export async function crearUsuario(dto) {
  return Usuario.create(dto);
}

export async function buscarPorEmail(email) {
  return Usuario.findOne({ email }).select('+password');
}

// .populate reemplaza ObjectId por el documento completo
export async function pedidosDeUsuario(id) {
  return Usuario.findById(id).populate('pedidos');
}

ORM moderno: Prisma

Prisma genera un cliente tipado a partir de un esquema declarativo, ofreciendo autocompletado y seguridad de tipos en TypeScript. Soporta PostgreSQL, MySQL, SQLite, SQL Server y MongoDB.

prisma/schema.prisma 
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Usuario {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  nombre    String
  password  String
  pedidos   Pedido[]
  creadoEn  DateTime @default(now())
}

model Pedido {
  id        Int      @id @default(autoincrement())
  total     Decimal  @db.Decimal(10, 2)
  usuario   Usuario  @relation(fields: [usuarioId], references: [id])
  usuarioId Int
}
using Prisma Client 
import { PrismaClient } from '@prisma/client';
const prisma = new PrismaClient();

// Read con relaciones incluidas (no N+1)
const usuarioConPedidos = await prisma.usuario.findUnique({
  where: { id: 1 },
  include: { pedidos: true }
});

// Create en dos tablas en una sola transacción
const nuevo = await prisma.usuario.create({
  data: {
    email: 'ana@demo.com',
    nombre: 'Ana',
    password: hash,
    pedidos: { create: [{ total: 99.5 }] }
  },
  include: { pedidos: true }
});

Transacciones ACID

Una transacción agrupa varias operaciones que deben ejecutarse atómicamente: o se completan todas, o ninguna. Las propiedades ACID son:

  • Atomicidad: todo o nada.
  • Consistencia: el esquema y restricciones se respetan.
  • Aislamiento: transacciones concurrentes no interfieren.
  • Durabilidad: una vez commiteada, persiste ante fallos.
Transferencia bancaria como transacción SQL 
const client = await pool.connect();
try {
  await client.query('BEGIN');

  await client.query('UPDATE cuentas SET saldo = saldo - $1 WHERE id = $2', [monto, origen]);
  await client.query('UPDATE cuentas SET saldo = saldo + $1 WHERE id = $2', [monto, destino]);
  await client.query('INSERT INTO transferencias (origen, destino, monto) VALUES ($1,$2,$3)', [origen, destino, monto]);

  await client.query('COMMIT');
} catch (err) {
  await client.query('ROLLBACK');
  throw err;
} finally {
  client.release();
}

Índices y rendimiento

Un índice es una estructura auxiliar que acelera las consultas WHERE y JOIN a costa de ocupar más espacio y ralentizar las escrituras. Buenas prácticas:

  • Crea índices sobre columnas usadas frecuentemente en filtros y foreign keys.
  • Usa índices compuestos respetando el orden de las columnas del WHERE.
  • Audita consultas lentas con EXPLAIN ANALYZE en PostgreSQL.
  • Evita el SELECT *; pide solo las columnas necesarias.
  • Pagina grandes listas con LIMIT/OFFSET o, mejor, keyset pagination.
⚠️ Evita el problema N+1

Si por cada usuario de una lista haces otra consulta para sus pedidos, harás 1 + N consultas. Usa include en Prisma, populate en Mongoose o un JOIN en SQL para resolverlo en una sola ida.
