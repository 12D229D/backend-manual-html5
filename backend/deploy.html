🚀 Guía Práctica de Despliegue & DevOps

LLevar una aplicación Node.js a producción va más allá del código: contenerización, gestión de secretos, procesos robustos, CI/CD automatizado, terminación TLS y observabilidad. Aquí tienes el flujo completo.

Ciclo DevOps

DevOps unifica Desarrollo (Dev) y Operaciones (Ops) en un único flujo iterativo basado en automatización, feedback y métricas. El ciclo típico es:

PlanRequisitos, backlog, ticketsJira, Linear, GitHub Issues

ReleaseEmpaquetar imagen, tag semverDocker, GitHub Packages

Operate & MonitorLogs, métricas, alertasGrafana, Prometheus, Sentry

Docker & Contenedores

Docker empaqueta tu app junto con sus dependencias y sistema operativo base en una imagen reproducible. El siguiente Dockerfile usa multi-stage para producir imágenes pequeñas.

Dockerfile - multi-stage 
# ---- Stage 1: build deps ----
FROM node:20-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev

# ---- Stage 2: runtime ----
FROM node:20-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production

COPY --from=deps /app/node_modules ./node_modules
COPY . .
USER node                                       # No usar root
EXPOSE 3000
CMD ["node", "src/server.js"]
docker-compose.yml - app + postgres 
services:
  api:
    build: .
    ports: ["3000:3000"]
    environment:
      - DATABASE_URL=postgresql://user:pass@db:5432/mi_db
      - JWT_SECRET=${JWT_SECRET}
    depends_on: [db]

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass
      POSTGRES_DB: mi_db
    volumes: ["pgdata:/var/lib/postgresql/data"]

volumes:
  pgdata:
.dockerignore es esencial

Incluye node_modules, .env, .git, dist en .dockerignore para no copiarlos al contexto de build y acelerar las imágenes evitando filtrar secretos.

PM2: procesos Node robustos

Si no usas Docker, pm2 es el estándar para ejecutar Node en producción: reinicia en crash, balancea con cluster mode y guarda logs.

ecosystem.config.cjs - cluster mode 
module.exports = {
  apps: [{
    name: 'mi-backend',
    script: 'src/server.js',
    instances: 'max',        // usa todos los núcleos
    exec_mode: 'cluster',
    max_memory_restart: '400M',
    env:     { NODE_ENV: 'production' }
  }]
};

// Comandos:
// pm2 start ecosystem.config.cjs
// pm2 logs            → ver logs en vivo
// pm2 reload all      → reinicio sin downtime
// pm2 monit           → panel de CPU/memoria

CI/CD con GitHub Actions

El siguiente workflow corre tests y construye la imagen Docker en cada push a main:

.github/workflows/ci.yml 
name: CI - Build & Test

on:
  push:
    branches: [main]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npm run lint
      - run: npm test -- --coverage
      - name: Build Docker image
        run: docker build -t mi-backend:${{ github.sha }} .
      - name: Login & Push
        if: github.ref == 'refs/heads/main'
        run: |
          echo "${{ secrets.REGISTRY_TOKEN }}" | docker login -u ${{ secrets.REGISTRY_USER }} --password-stdin
          docker tag  mi-backend:${{ github.sha }} ${{ secrets.REGISTRY }}/mi-backend:latest
          docker push ${{ secrets.REGISTRY }}/mi-backend:latest

Reverse Proxy con Nginx y TLS

En producción, no expongas Node directamente a Internet. Un reverse proxy (Nginx/Caddy/Traefik) termina TLS, aplana logs, comprime respuestas y filtra tráfico.

nginx - reverse proxy a Node 
server {
    listen 443 ssl http2;
    server_name api.midominio.com;

    ssl_certificate     /etc/letsencrypt/live/api.midominio.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.midominio.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
💡 Caddy con TLS automático

Si no quieres gestionar certificados manualmente, Caddy emite y renueva certificados Let's Encrypt automáticamente con una sola línea: api.midominio.com { reverse_proxy localhost:3000 }.

Logs y observabilidad

  • Emite logs en JSON estructurado ( Winston, pino ) para ingestión en ELK/Loki.
  • Aplica niveles correctos: debug, info, warn, error.
  • No registres credenciales, tokens ni PII sensible.
  • Integra monitorización de errores con Sentry, Rollbar o Datadog.
  • Recolecta métricas (latencia, tasa de error, peticiones por segundo) con Prometheus + Grafana.
  • Implementa healthchecks en /health y /ready para orquestadores.
src/server.js - endpoint /health 
app.get('/health', async (req, res) => {
  try {
    await pool.query('SELECT 1');
    res.json({ status: 'ok', uptime: process.uptime(), db: 'connected' });
  } catch (err) {
    res.status(503).json({ status: 'down', db: err.message });
  }
});
