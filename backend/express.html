🚂 Guía Práctica de Express.js

Express es el framework web más usado para Node.js. Minimalista, flexible y extensible mediante middlewares, es la base ideal para construir APIs REST y aplicaciones web renderizadas en el servidor.

¿Qué es Express.js?

Express es un framework minimalista y no opinado para Node.js creado por TJ Holowaychuk en 2010. No impone arquitectura, ORM ni estructura de carpetas, sino que proporciona:

  • Sistema de enrutado basado en verbos HTTP (app.get, app.post, …).
  • Encadenamiento de middlewares con la función next().
  • Helpers de petición/respuesta (req.body, req.params, req.query, res.json).
  • Soporte de motores de plantillas (EJS, Pug, Handlebars).
Instalación e inicialización 
npm init -y
npm install express
npm install --save-dev nodemon

Estructura recomendada del proyecto

Como Express no impone estructura, conviene adoptar una organización modular desde el inicio:

Estructura de carpetas 
src/
├── config/        # variables de entorno, conexión BD
│   └── env.js
├── middlewares/   # auth, validaciones, errores
│   ├── auth.js
│   └── errorHandler.js
├── routes/        # definición de endpoints
│   ├── usuarios.routes.js
│   └── auth.routes.js
├── controllers/   # lógica de cada ruta
│   └── usuarios.controller.js
├── services/      # lógica de negocio reutilizable
│   └── usuarios.service.js
├── models/        # esquemas de BD / Prisma
│   └── usuario.model.js
└── server.js      # punto de entrada
💡 Patrón Modelo-Vista-Controlador

Separar rutas (qué URL), controladores (qué hace) y servicios (cómo se hace) facilita probar cada capa de forma aislada y mantener el código ordenado a medida que crece.

Sistema de rutas y Express Router

Para mantener un server.js limpio, conviene separar las rutas en módulos y montarlos con app.use().

src/routes/usuarios.routes.js 
import { Router } from 'express';
import { listarUsuarios, crearUsuario, obtenerUsuario } from '../controllers/usuarios.controller.js';

const router = Router();

router.get('/',        listarUsuarios);
router.post('/',       crearUsuario);
router.get('/:id',     obtenerUsuario);
router.put('/:id',     actualizarUsuario);
router.delete('/:id',  eliminarUsuario);

export default router;
src/server.js - montaje de rutas 
import express from 'express';
import usuariosRouter from './routes/usuarios.routes.js';
import authRouter     from './routes/auth.routes.js';

const app = express();

app.use(express.json());                   // body parser JSON
app.use('/api/v1/usuarios', usuariosRouter);
app.use('/api/v1/auth',     authRouter);

const PORT = process.env.PORT ?? 3000;
app.listen(PORT, () => console.log(`API en :${PORT}`));
GET /api/v1/usuarios?pagina=1&limite=20

Los parámetros de query se leen en req.query para implementar paginación, filtros y ordenamiento.

POST /api/v1/usuarios

El cuerpo JSON de la petición se accede vía req.body, ya parseado por el middleware express.json().

Middlewares en Express

Un middleware es una función (req, res, next) => {}. Express los ejecuta en el orden en que se registran. Algunos tipos comunes:

Middleware Rol típico
express.json()Parsear body JSON entrante.
express.static()Servir ficheros estáticos (CSS, JS, imágenes).
morganLogger HTTP con formato dev/combined.
corsConfigurar cabeceras CORS.
helmetCabeceras de seguridad HTTP por defecto.
express-rate-limitThrottling / rate limiting por IP.
Verificador JWTValidar token Bearer y popular req.user.
middlewares/auth.js - guard JWT 
import jwt from 'jsonwebtoken';

export function verificarToken(req, res, next) {
  const header = req.headers.authorization;
  if (!header?.startsWith('Bearer ')) {
    return res.status(401).json({ error: 'Token no proporcionado' });
  }
  const token = header.split(' ')[1];
  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    return res.status(401).json({ error: 'Token inválido o expirado' });
  }
}

// Ruta protegida
router.get('/perfil', verificarToken, obtenerPerfil);

Manejo centralizado de errores

Express reconoce middlewares con 4 parámetros (err, req, res, next) y los trata como manejadores de error. Conviene registrar el último de todos, después de todas las rutas:

middlewares/errorHandler.js 
export function errorHandler(err, req, res, next) {
  console.error(err.stack);

  // Error de validación (Zod, Joi, express-validator)
  if (err.name === 'ValidationError') {
    return res.status(400).json({ error: 'Datos inválidos', detalles: err.details });
  }

  // Error emitido por nosotros con statusCode
  const status = err.statusCode ?? 500;
  res.status(status).json({
    error: err.message || 'Error interno del servidor',
    ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
  });
}

// En server.js, DESPUÉS de todas las rutas:
app.use(errorHandler);
✅ Buenas prácticas

Envuelve los controladores asíncronos con asyncHandler o express-async-errors para que las promesas rechazadas lleguen al middleware de errores automáticamente sin try/catch manuales.
