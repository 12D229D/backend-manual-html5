Arquitectura Cliente-Servidor

El backend es la capa del servidor que gestiona la lógica de negocio, persistencia de datos y exposición de APIs que el frontend consume. En una arquitectura típica de 3 capas (three-tier) encontramos:

Capa Responsabilidad Tecnologías típicas
Presentación Interfaz de usuario, renders, peticiones al backend. React, Vue, HTML5/CSS3, Fetch API
Lógica de Negocio Reglas de negocio, validaciones, middlewares, orquestación. Node.js + Express, Python (Django/FastAPI), Java (Spring)
Persistencia Almacenamiento duradero, consultas, integridad de datos. PostgreSQL, MySQL, MongoDB, Redis
💡 ¿Por qué usar una arquitectura por capas?

La separación de responsabilidades facilita el mantenimiento, permite escalar y reemplazar capas de manera independiente, y mejora la testabilidad del sistema.

Middlewares y Rutas HTTP

Un middleware es una función que se ejecuta entre la recepción de la petición y la respuesta final. Express los encadena en orden de registro. Pueden leer/modificar req y res, y decidir si continúan con next().

GET /api/v1/usuarios

Devuelve la lista de usuarios. Aplica middlewares de autenticación, log y validación previamente.

POST /api/v1/usuarios

Crea un nuevo usuario. Verifica el body de la petición, valida el esquema, hashea la contraseña y persiste en BD.

DELETE /api/v1/usuarios/:id

Elimina un usuario existente por su identificador. Requiere rol de administrador.

express - cadena de middlewares 
const express = require('express');
const app = express();

// Middleware global: logger
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url} - ${new Date().toISOString()}`);
  next();
});

// Middleware integrado: parse JSON body
app.use(express.json());

// Ruta con múltiples middlewares encadenados
app.post('/api/v1/usuarios',
  validarSchema,
  hashearPassword,
  crearUsuario,
  (req, res) => res.status(201).json(req.usuario)
);

app.listen(3000, () => console.log('Server on :3000'));

ORM y Capa de Datos

Un ORM (Object-Relational Mapping) abstrae la base de datos en modelos de objetos del lenguaje, evitando escribir SQL crudo y reduciendo el riesgo de inyección SQL. Algunos populares:

  • Prisma — Genera un cliente tipado a partir de un esquema declarativo. Excelente DX con TypeScript.
  • Sequelize — ORM maduro para Node.js con soporte para PostgreSQL, MySQL, SQLite y MSSQL.
  • TypeORM — Inspirado en Hibernate (Java), soporta patrón Active Record y Data Mapper.
  • Mongoose — Modelado de objetos para MongoDB con esquemas y validaciones.
⚠️ Cuidado con el patrón N+1

Los ORM pueden generar involuntariamente una consulta adicional por cada elemento de una lista (problema N+1). Usa include, populate o eager loading para evitarlo en lecturas relacionadas.

Variables de Entorno (.env)

Las credenciales, puertos, URLs de base de datos y secretos nunca deben ir en el código fuente. Se almacenan en variables de entorno típicamente cargadas con el paquete dotenv.

.env (no se commitea, va en .gitignore) 
PORT=3000
NODE_ENV=development
DATABASE_URL=postgresql://user:pass@localhost:5432/mi_db
JWT_SECRET=cadena_super_secreta_de_64_chars
JWT_EXPIRES_IN=2h
CORS_ORIGIN=http://localhost:5173
🚨 Peligro de seguridad

Nunca expongas JWT_SECRET o DATABASE_URL en el frontend, en repositorios públicos, ni en logs del servidor. Usa un gestor de secretos (Vault, AWS Secrets Manager) en producción.
